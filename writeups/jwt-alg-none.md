# JWT alg:none — обход проверки подписи (OWASP Juice Shop)

## Summary
Приложение не проверяет подпись, если в header указан alg:"NONE". Благодаря этому подделывается payload и есть возможность сменить пользователя на любого существующего и обойти авторизацию.

## CWE
CWE-347 — Improper Verification of Cryptographic Signature
(+ можно CWE-345 — недостаточная проверка подлинности данных)

## Severity
Оценка: Critical - рушится вся система идентификации пользователей. Приложение не может больше доверять ни одному токену, так как любой из них может быть подделан. Эксплуатируется тривиально готовым инструментом, без спец-условий

## Root cause
Ошибка дизайна: сервер определяет алгоритм по полю alg из самого токена - то есть доверяет данным, которые контролирует атакующий. Проверяющая сторона не должна принимать от проверяемой решение о том, как её проверять. Ошибка реализации (blocklist=="none", пропускающий NONE). payload — открытый Base64

## Steps to Reproduce (PoC)
1. Логин, получить токен (alg: RS256).
2. *python3 jwt_tool <token>* / ручная сборка: header {"alg":"NONE"}, payload с role:admin, пустая подпись. Сменил role:"customer" на "admin"
3. Удалить If-None-Match, подставить Authorization: Bearer <токен>.
4. GET /rest/admin/application-configuration → 200 + админский конфиг.

## Impact
Атакующий контролирует весь payload и может выполнить горизонтальную (действовать от имени любого пользователя) и вертикальную (role: customer -> admin) эскалации. Так как подделан может быть любой токен, сервер больше не может доверять ни одному токену. Это полный обход аутентификации и авторизации для всех учеток.

## Fix
Allowlist: сервер принимает ТОЛЬКО RS256, игнорирует alg из токена.
Ссылка на principles.md → allowlist > blocklist.

## Detection (как поймать в пайплайне)
DAST/ручной тест ловит надежно (jwt_tool -X a). SAST должен увидеть: код проверки токена, где алгоритм берется из самого токена. При кастомной логике проверки - может пропустить.
Рождается на Design, дешевле всего предотвращается threat modeling'ом, ловится на этапе Testing
