# Beach Bar (TryHackMe, Hacker Holidays) — write-up

## Summary
Небезопасная обработка файла .yml вместе с двумя дополнительными уязвимостями привели к RCE и privesc до root.

## Этап 1 — Recon
- nmap: нашёл — порт :80, gunicorn → Python
- приложение принимает и обрабатывает файл .yml

## Этап 2 — Точка входа: YAML deserialization RCE
- **Уязвимость:** небезопасный парсер yaml.load вместо safe_load
- **Где:** форма импорта плейлиста, .yml
- **Как:** payload с !!python/object → выполнение кода. Ответ (0,) = blind RCE

## Этап 3 — Reverse shell
- **Проблема:** спецсимволы reverse shell ломали кавычки payload
- **Решение:** base64-обёртка
- → shell как юзер приложения → user.txt

## Этап 4 — Privesc
- **Вектор:** пароль в ps aux — в аргументах процесса --stream-pass
- **Как:** su root с этим паролем — переиспользование
- → root.txt

## Root cause (почему сработало)
1. YAML: yaml.load дал RCE, потому что обрабатывал файл небезопасным методом yaml.load() вместо safe_load()
2. Privesc: пароль передавался в аргументе команды, поэтому в выводе ps aux был найден пароль и использован для смены пользователя на root

## CWE
- CWE-502 — Deserialization of Untrusted Data
- CWE-214 — Sensitive Arguments (пароль в ps aux)
- CWE-521 — переиспользование пароля

## Severity
Critical - полный контроль на приложением с правами root.

## Impact
От анонимного пользователя (форма импорта, без авторизации) до полного контроля над хостом (root). Доступ ко всем данным и сервисам.

## Fix
1. YAML — safe_load
2. секрет — не в аргументы (использовать переменные окружения, .env)
3. пароли — не переиспользовать (один сервис - один пароль)

## Detection
SAST: находит небезопасную обработку файла yaml.load
DAST: отправка yaml-payload
Process/config audit: секреты в аргументах процессов (пароль виден в ps aux) - сканеры конфигурации это ловят.
SDLC: yaml.load — рождается на этапе Coding, ловится на code review (grep yaml.load)
и SAST. Секрет в аргументах — на code review / аудите конфигурации

## Инструменты
nmap, nc, curl/Burp, base64

## Уроки
1. Нельзя доверять вводу пользователя (производить безопасную обработку ввода)
2. Не хранить секреты в аргументах
3. Не переиспользовать пароли
