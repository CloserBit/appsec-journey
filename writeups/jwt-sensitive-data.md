Что: JWT payload содержит password и totpSecret.

Root cause: payload — Base64, не шифрование; читается без ключа; в токен положили чувствительные поля.
CWE-522 — Insufficiently Protected Credentials (Недостаточно защищенные учетные данные) (точный: утекли креды)
CWE-200 — Exposure of Sensitive Information (Разглашение конфиденциальной информации) (общий контекст)

Как нашёл: декодировал свой токен (jwt.io / base64 -d), увидел поля.

Severity: High - утечка credentials(totpSecret, хэш-пароля), ведущая к компрометации аутентификации, из-за чего при доп. действиях(брутфорс) можно увести аккаунт.

Impact: утечка (браузерное хранилище, логи сервера, истории браузера, кэшах, Referer-заголовках, системах мониторинга) хеша пароля (offline-брут) + компрометация 2FA (totpSecret) при любом перехвате/логировании токена.

Detection:
SAST: при явном указании сохраняемых данных в токене. Пропускает, если в токен идёт объект целиком — sign(user) — где password спрятан внутри
объекта (статически не видно). В Juice Shop именно так → SAST молчит.
DAST/ручной: выявляется железно (декодировка Base64 любого токена)
SDLC: Рождается в Design, а ловится на code review.

Fix: в payload класть только идентификатор и роль (sub, role), никаких паролей/секретов; чувствительные данные держать на сервере.
Пароль: только хеш (bcrypt/argon2) в БД, в токен не попадает вообще.
totpSecret и секреты: в БД шифрованными, только на сервере
