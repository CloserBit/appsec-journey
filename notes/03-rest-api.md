REST — способ строить API: адрес = вещь (/users/24), метод = действие (GET читать, POST создать, PUTменять, DELETE удалить).
IDOR — меняешь номер объекта в запросе на чужой (/users/24 → /users/25), сервер отдаёт чужое, потому что не проверил принадлежность. Живёт на авторизации (не аутентификации): ты залогинен честно, но лезешь к чужому объекту. Предсказуемые REST-адреса → перебор id → массовый IDOR.
*сервер забыл* — называется проверка авторизации на уровне объекта (принадлежит ли этот конкретный объект тебе)
аутентификация = «ты вошёл» (это сработало)
авторизация = «тебе можно именно этот объект» (это забыли) - IDOR

Идемпотентность — повтори действие N раз, результат тот же. GET/PUT/DELETE идемпотентны, POST — нет (каждый POST создаёт новое).
Атака: POST не идемпотентен → перехватил POST /transfer, повторил 5 раз → 5 переводов (replay). Защита — idempotency-key: сервер по метке распознаёт повтор и не делает дважды. Проверяй: защищены ли POST-операции (переводы/покупки) от повтора?
Версионирование — /api/v1, /api/v2; старое издание живёт ради старых клиентов. Ловушка: фикс накатили на v2, а v1 забыли → старая дыра жива. Рефлекс: нашёл эндпоинт → проверь v1/old/legacy.
