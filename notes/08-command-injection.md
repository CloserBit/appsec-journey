*Command Injection* — пользовательский ввод вырывается в команду ОС (shell), а не SQL. Тот же корень, другой интерпретатор.
Возникает: приложение вызывает системную команду (ping, конвертация) и склеивает ввод: os.system("ping " + input).
Разделители команд в shell: ; (потом), | (пайп), && (если успех), ` / $() (подстановка).
Атака: input = "google.com; whoami" → ping ...; whoami → выполняется твоя команда на сервере.
ОПАСНОСТЬ: это RCE (Remote Code Execution) — выполнение команд на сервере, чтение файлов, захват. Тяжелее SQLi (там БД, тут весь сервер). Severity Critical.
Виды: in-band (вывод команды виден) / blind (не виден → задержка ; sleep 10, или out-of-band ; nslookup свой-домен).
Корень: смешение данных и команды (как SQLi). Фикс — не склеивать ввод в команду.

*Защита command injection* (похожа на SQLi):
1. ГЛАВНОЕ — не вызывать системные команды, если есть библиотечная функция языка (DNS-либа вместо nslookup). Нет shell — нет инъекции.
2. Если команда нужна — передавать аргументы РАЗДЕЛЬНО массивом + shell=False: subprocess.run(["ping","-c","1",input], shell=False). Ввод = буквальный аргумент, shell не разбирает ; | &. (Аналог параметризации: команда и данные раздельно.)
3. allowlist для ввода из известного набора.
4. least privilege процесса ОС → снижает impact RCE.
НЕ фильтрация символов (; | &) — blocklist дырявый: разделителей много (| && || \n ` $()), обходится.
Как в SQLi: разделять команду и данные, не чистить символы!

*Важно:* защищает не subprocess сам по себе, а СПИСОК аргументов + shell=False. subprocess.run("ping "+input, shell=True) — так же уязвим (shell вернулся). Ключ: не звать shell + аргументы раздельно.

*Как работает shell=False:* программу (ping) запускает ОС НАПРЯМУЮ, а не через shell. Shell — лишь один способ запуска (удобный, но опасный: он РАЗБИРАЕТ строку, видит ; | и запускает доп. команды).
subprocess([...], shell=False): ОС берёт ping и отдаёт ему аргументы списком буквально. ; whoami внутри аргумента = часть имени хоста (символ), НЕ команда — некому разобрать (shell выпал). ping выполнится (не найдёт хост), whoami — нет.
Суть: убираешь интерпретатора (shell) → разделители перестают работать.

*Зачем shell (если он так опасен):* даёт ФИЧИ, которых нет у прямого запуска — пайпы (|), перенаправление (> <), переменные/подстановки ($HOME, $()), wildcards (*), скрипты (циклы). Прямой запуск (shell=False) умеет только «запусти программу с аргументами».
Дилемма: нужны фичи → зовёшь shell → удобно, но открыта инъекция. Не нужны → прямой запуск → безопасно.
AppSec-вывод: большинство приложений НЕ нуждаются в фичах shell (просто «запусти ping»), зовут его по привычке — и создают дыру. Принцип LEAST POWER: бери самый простой инструмент, достаточный для задачи. Не тащи shell туда, где хватит прямого запуска (родственник least privilege).
