# Recon-чеклист для веб-целей (CTF / THM / HTB)

Держи открытым при решении. Цель — не «пялиться на цель», а идти по шагам.
Главное правило: на реальной цели тип уязвимости НЕ назван — ты определяешь сам.
Методично проходи точки ввода, не ищи «сразу баг».

---

## 0. Первичное сканирование (если дан IP/хост)
- [ ] `nmap -sV -sC <IP>` — какие порты/сервисы открыты, версии
- [ ] Какой веб-сервер, порт (80/443/8080)? Записать версии — гуглить известные CVE
- [ ] Добавить хост в /etc/hosts, если нужно (THM часто требует)

## 0.5. OSINT — пассивная разведка (до активного сканирования)

Сбор информации из ОТКРЫТЫХ источников, не трогая цель напрямую.
Идёт ПЕРЕД nmap: чем больше знаешь до контакта, тем точнее атака.

**Инструменты:**
- [ ] **theHarvester** (github.com/laramies/theHarvester) — сбор email, поддоменов,
      имён, хостов по домену из публичных источников (поисковики, PGP, Shodan).
      `theHarvester -d target.com -b all`
- [ ] **OSINT Framework** (osintframework.com) — каталог OSINT-инструментов по
      категориям (email, соцсети, домены, метаданные). Навигатор, что чем искать.
- [ ] **Hunter.io** (https://hunter.io) - поиск и сбор email людей, связанных с различными доменами и сервисами.

**Что собирать на этом этапе:**
- поддомены (расширяют поверхность атаки)
- email-адреса (для username enumeration, фишинга в red team)
- используемые технологии, утёкшие данные (breaches)
- метаданные документов, публичные репозитории (случайные утечки ключей)

**Принцип:** OSINT пассивен — цель не видит твою разведку. Активное сканирование
(nmap) оставляет следы, OSINT — нет. Сначала выжми открытые источники.

## 1. Mapping — осмотреть приложение целиком
- [ ] Пройти по ВСЕМ страницам/функциям вручную. Что делает приложение?
- [ ] Burp Proxy включён — просто ходи по сайту, Burp соберёт site map (карту)
- [ ] Выписать ВСЕ точки ввода:
  - формы (логин, поиск, регистрация, контакт, загрузка файлов)
  - параметры URL (?id=, ?page=, ?file=)
  - cookie (что в них? Base64? сериализованный объект?)
  - заголовки (User-Agent, Referer — иногда логируются в БД)
- [ ] Зарегистрироваться / залогиниться — что доступно под юзером?

## 2. Исходники и «улики»
- [ ] View Source каждой страницы — комментарии разработчика, скрытые поля
- [ ] `/robots.txt`, `/sitemap.xml` — скрытые пути
- [ ] JS-файлы — эндпоинты, API-пути, ключи, логика (грепать на "api", "admin", "token")
- [ ] Заголовки ответов — сервер, технологии, X-Powered-By
- [ ] Комментарии `<!-- -->` в HTML — часто выдают пути/логику

## 3. Fingerprinting — определить технологии
- [ ] Wappalyzer (расширение) — стек: PHP/Node/Python? CMS? фреймворк?
- [ ] По стеку → гуглить известные уязвимости/CVE этой версии
- [ ] Расширения файлов (.php/.aspx/.jsp) — какой язык бэкенда

## 4. Перебор скрытого (fuzzing)
- [ ] Директории/файлы: `ffuf` / `gobuster` / `dirb`
      `ffuf -u http://target/FUZZ -w wordlist.txt`
  - искать: /admin, /backup, /.git, /api, /dev, /test, /config
- [ ] Параметры: если есть ?x= — фаззить имена параметров
- [ ] Поддомены (если в скоупе): ffuf по vhost

## 5. По КАЖДОЙ точке ввода — прогнать классы уязвимостей
Для каждого параметра/формы спроси «куда это идёт?» и пробуй:

| Признак точки ввода | Что пробовать | Payload-старт |
|---|---|---|
| идёт в БД (поиск, логин, id) | SQLi | `'` , `' OR 1=1--` , `' UNION SELECT...` |
| отражается на странице | XSS | `<script>alert(1)</script>` , `<img src=x onerror=alert(1)>` |
| путь/id объекта (?id=, /user/5) | IDOR | поменяй id на чужой |
| системная команда (ping, конверт) | Command Injection | `;whoami` , `\| whoami` , `&& id` |
| URL/редирект (?url=, ?redirect=) | SSRF / Open Redirect | `http://localhost` , `http://169.254.169.254` |
| загрузка файла | File Upload | загрузить .php/.jsp шелл, обойти фильтр |
| путь к файлу (?file=, ?page=) | Path Traversal / LFI | `../../../etc/passwd` |
| сериализованный объект в cookie | Десериализация | декодировать, изменить поле |
| токен/JWT | JWT-атаки | alg:none, confusion, слабый секрет |

## 6. Аутентификация/сессии (если есть логин)
- [ ] Username enumeration (разница ответов на существующий/нет логин)
- [ ] Брутфорс (если нет rate limit) — Hydra / Burp Intruder + словарь
- [ ] Дефолтные креды (admin/admin, admin/password) — всегда пробуй!
- [ ] Логика сессии: cookie предсказуема? JWT подделываем?
- [ ] Password reset / 2FA логика — подмена username в запросе

## 7. Автоматизация (осторожно — на CTF часто нужна голова, не сканер)
- [ ] Nuclei — прогнать шаблоны известных уязвимостей
- [ ] Nikto — быстрый веб-скан (шумный)

## Если ЗАСТРЯЛ (главное для CTF)
1. Вернись к точкам ввода — какую НЕ проверил?
2. Перечитай ВСЁ, что вернул сервер (ошибки, комментарии, заголовки) — улики там
2. Попробуй дефолтные креды и /robots.txt — часто забывают
4. Погугли стек + версию + "exploit" / "CVE"
5. Не решил за разумное время → посмотри write-up, пойми ЧТО упустил в recon
   (учиться на разборе — нормально и быстро)

## Принципы
- Тип уязвимости не назван — определяешь по «куда идёт ввод»
- Не ищи «сразу баг» — методично перебирай точки ввода по чеклисту
- Читай ВСЁ, что отвечает сервер — улики в ошибках/комментариях/заголовках
- Насмотренность растёт с объёмом целей + разбором чужих write-up
- Дефолтные креды и /robots.txt проверяй ВСЕГДА (частая забывчивость)

## 8. Privilege Escalation (когда получил shell на машине)

Цель: из низкоправного юзера (www-data/user) → root. Финал большинства машин.

### Быстрый старт — автоматический enum
- [ ] Залить и запустить LinEnum / LinPEAS (см. tools.md) — соберёт все векторы разом
- [ ] Прочитать отчёт, отметить подсвеченное "интересное"

### Ручная проверка векторов (если нет скрипта / проверить точечно)
- [ ] `sudo -l` — разрешённые от root команды → GTFOBins для эксплуатации
- [ ] `find / -perm -4000 -type f 2>/dev/null` — SUID (права владельца=root) → GTFOBins
- [ ] `cat /etc/crontab`, `ls -la /etc/cron.*` — cron-задачи с изменяемым скриптом
- [ ] `uname -a` — версия ядра → поиск kernel privesc exploit
- [ ] слабые права: `/etc/passwd` writable? читаемые ключи/пароли в /home, конфигах?
- [ ] `getcap -r / 2>/dev/null` — capabilities
- [ ] `history`, `~/.bash_history` — пароли в истории?

### Принципы
- Внутри машины → путь ИЗНУТРИ (recon ФС, не внешний брутфорс)
- Один вектор не сработал → LinPEAS покажет другие, проверяй систематически
- GTFOBins (gtfobins.github.io) — как эксплуатировать найденную sudo/SUID команду
- Не создавать файлы через sudo (владелец root); работать в /tmp или ~
