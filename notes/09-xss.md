*XSS (Cross-Site Scripting)* — инъекция в БРАУЗЕР ДРУГОГО пользователя. Ввод атакующего исполняется как JavaScript в браузере жертвы. Жертва — не сервер, а другой юзер; сервер — посредник, доставляющий вредоносный JS.
Механика: браузер исполняет любой JS на странице. Протащить свой <script> так, чтобы браузер жертвы выполнил. Пример: коммент <script>alert('XSS')</script> → сайт показал другим без обработки → их браузер выполнил.
Корень: смешение данных и кода (как SQLi/command), но интерпретатор — БРАУЗЕР. Ввод (данные) стал JavaScript (код).
Опасность: кража session cookie (угон сессии), действия от имени жертвы, кража данных со страницы, фишинг, кейлоггер. Контроль сессии жертвы.

*Экранирование (escaping)* — защита XSS. Замена спецсимволов HTML на безопасные текстовые эквиваленты (HTML-сущности): < → <  > → >  " → "  ' → '  & → &.
Без экранирования: <script> вставлен как тег → браузер ВЫПОЛНЯЕТ → XSS.
С экранированием: <script> → браузер видит ТЕКСТ, показывает буквами «<script>», НЕ выполняет.
Суть: превращает потенциальный код в безобидный текст. Браузер рисует < > как символы, не как разметку.
Это НЕ blocklist (не запрет символов, не фильтр тегов — обходится), а ПРЕОБРАЗОВАНИЕ: ввод структурно не может стать кодом (как параметризация в SQLi).
Принцип: экранировать ВЫВОД (при показе), под КОНТЕКСТ вставки (HTML-тело / атрибут / JS — правила разные).

*Reflected vs DOM*— разница В ТОМ, КТО ВСТАВЛЯЕТ ввод в страницу:
Reflected: ввод → на СЕРВЕР → сервер вставляет его в HTML-ответ → браузер выполняет. Сервер payload ВИДЕЛ (отразил). Уязвимость в серверном коде.
DOM: ввод (часто после # — на сервер НЕ уходит) → КЛИЕНТСКИЙ JS страницы сам читает URL и вставляет в DOM (innerHTML=location.hash) → выполняется. Сервер payload НЕ видел. Уязвимость в клиентском JS.
Аналогия: reflected — секретарь (сервер) переписал твою записку на доску; DOM — робот в комнате (клиентский JS) сам прочитал записку с двери и переписал, секретарь не видел.

*innerHTML* — свойство элемента: его HTML-содержимое. Чтение (что внутри) и запись (замена). ВАЖНО: вставляет строку КАК HTML — теги в ней становятся настоящими (<b> → жирный, <img onerror> → выполнится).
textContent — вставляет как ТЕКСТ (теги показываются буквами, не срабатывают). Безопасно.
DOM-XSS: element.innerHTML = ввод → теги из ввода выполняются. Защита — textContent вместо innerHTML для данных.
