SDLC (Software Development Life Cycle) - жизненный цикл разработки ПО.

SSDLC (Secure Software Development Life Cycle) - жизненный цикл разработки ПО, в каждый этап которого встроены активности по безопасности

*Классические этапы:*
1. Requiriments - сбор требований  - ("хранить пароли хэшированными, "rate-limit на login")
2. Design - проектировка архитектуры приложения («а как это можно атаковать?» на уровне схемы)
3. Implementation/Coding - написание кода - SAST (линтер безопасности прямо в IDE/CI)
4. Testing - тестирование - DAST, пентест (скан работающего приложения, проверка зависимостей)
5. Deployment - прода - Secure config, secrets-management (не выкатить дефолтные пароли, закрыть debug)
6. Maintenance - сопровождения/обновления - Патчи, мониторинг, реагирование на CVE

"Shift Left" - смещение момента обнаружения уязвимости на этапе ее создания, чтобы сделать максимально дешевым предотвращение подобных проблем  в будущем.
Уязвимости намного дешевле исправить на этапе Design, нежели в Deployment (т.к. сверху накладываются таблицы, код, архитектура и т.д + атаки хакеров/найм пентестеров для устранения уязв.)
*переносим момент обнаружения с позднего этапа (Testing/Prod) на ранний (Coding/Design)*

STLC (Software Testing Life Cycle) - жизненный цикл тестирования, вложенный в этап Testing: планирование тестов → дизайн тест-кейсов → выполнение → отчёт → закрытие

*«рождается» = вносится в код/архитектуру (Design/Coding). «Ловится» = обнаруживается (Testing/Prod)*

Триаж — оценка + приоритизация находок: severity (серьёзность) × exploitability (лёгкость эксплуатации) × business impact (ущерб бизнесу) → что чинить первым. Плюс отсев ложных.
TP (true positive) — сканер прав, дыра есть. FP (false positive) — сканер ошибся, дыры нет (моя корзина в idor-скрипте). FN (false negative) — дыра есть, сканер промолчал (опаснее всего).
Scope по риску — тестировать в первую очередь высокорисковое (платежи, auth), а не всё равномерно.
SAST — мой код (статика). DAST — работающее приложение (динамика, снаружи). SCA — чужие зависимости/библиотеки (известные CVE).
Trivy/Grype — SCA-инструменты.

SCA (Software Composition Analysis) - инструменты для анализа состава ПО
