*Сериализация* — объект в памяти (User, корзина) → строка/байты (для хранения/передачи).
*Десериализация* — обратно строка → объект.
Форматы: JSON (текст, обычно безопасно); языко-специфичные бинарные (Python pickle, PHP serialize(), Java, .NET) — ОПАСНЫ.
Небезопасная десериализация: сервер десериализует данные, КОНТРОЛИРУЕМЫЕ атакующим (объект из cookie/запроса), без проверки. Десериализация не просто читает — ВОССТАНАВЛИВАЕТ объект, что может запускать код (конструкторы, магические методы).
Атака: подсунуть сконструированный сериализованный объект → при десериализации выполняется вредоносный код (часто RCE).
Корень: доверие данным атакующего, которые при обработке становятся исполняемым объектом. Класс тот же (доверие вводу), обёртка новая.  

*Modifying serialized data types:* обход через PHP type juggling. Меняешь s:32:"токен" (строка) → i:0 (число 0). Сервер сравнивает == (слабое, не ===): 0 == "любая_строка" → true в PHP < 8 (строка приводится к 0). Обходишь проверку токена БЕЗ знания токена.
Корень: PHP слабое сравнение == приводит типы. 0 == "foo" → true. Нужно === (строгое, тип+значение) для безопасности.
Категория: type juggling / loose comparison — реальный класс багов (не только десериализация; везде где == со сравнением секретов).
Защита: строгое сравнение ===, hash_equals() для токенов.
