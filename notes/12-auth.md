# Атаки на аутентификацию (A07 — Authentication Failures). Часто ЛОГИЧЕСКИЕ ошибки, не инъекции.
Векторы: брутфорс/слабые пароли, username enumeration, дефекты восстановления пароля, дефекты сессий (фиксация), обход 2FA.
Username enumeration: сайт выдаёт существование логина разницей ответов — текст ("invalid username" vs "invalid password"), длина, статус, ВРЕМЯ (существующий юзер дольше — проверка пароля). Перебираешь логины → находишь валидные → брутишь их пароли.
Защита enumeration: одинаковый ответ на любую ошибку ("invalid username or password"), одинаковое время, rate limiting.
Брутфорс: перебор паролей (Intruder + словарь). Работает без rate limiting / блокировки аккаунта.

*Timing-enumeration:* существование логина выдаёт ВРЕМЯ ответа. Логин не существует → сервер не нашёл юзера → пароль проверять не с чем → быстро. Логин существует → сервер ХЕШИРУЕТ введённый пароль (bcrypt/argon2 — намеренно медленные) и сравнивает → медленнее. Причина разницы — проверка пароля (хеширование), не «выгрузка логина». Timing attack (как time-based SQLi, но задержка естественная).

*Concurrent requests в Intruder* — сколько запросов шлётся ПАРАЛЛЕЛЬНО. Default 10 (для скорости). Но при 10 порядок на сервере НЕ гарантирован — запросы приходят вперемешку.
Для атак, зависящих от ПОРЯДКА (чередование wiener-сброс / carlos-брут), ставить Resource pool = 1 concurrent request — строго по очереди, порядок сохранён. Иначе чередование ломается (carlos набирает 3 подряд до сброса → блок).
Урок: атаки с последовательной логикой (сброс счётчика, race conditions наоборот) требуют 1 поток. Брутфорс без порядка — можно много потоков (быстрее).
