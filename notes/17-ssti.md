# SSTI (Server-Side Template Injection): сервер вставляет пользовательский ввод в ШАБЛОН (template engine) и выполняет как код шаблона.
Шаблонизаторы (EJS/Jinja2/Twig...) генерируют HTML, подставляя данные: <%= username %>. Если ввод юзера попадает в шаблон ДО обработки → становится кодом шаблона.
Тест: <%=77%> → вернулось 49 (не "77") = сервер выполняет ввод = SSTI.
RCE: через шаблон вызвать функции языка. Node.js/EJS: <%= global.process.mainModule.require('child_process').execSync("cmd") %>. Python/Jinja2: {{...}} свой синтаксис.
Корень: доверие вводу в исполняемом контексте (как SQLi/command injection/десериализация).
Тест-синтаксис по движку: EJS <%=77%>, Jinja2 {{77}}, разные {{ }}/<% %>/${ }.
Защита: не вставлять ввод в шаблон; sandboxed движки; экранирование.

- Reverse shell: ЖЕРТВА подключается к АТАКУЮЩЕМУ (не наоборот). "Reverse" = направление развёрнуто (обходит firewall — исходящие от жертвы разрешены). Ты на listener (nc -lvnp), жертва звонит тебе.
disk-группа: доступ к СЫРОМУ диску (/dev/sda) мимо файловой системы и прав ОС. debugfs читает блоки напрямую → содержимое защищённых файлов. НЕ права root, а *ОБХОД прав через низкоуровневый доступ.*
id → показывает группы (disk/docker/lxd/sudo/adm — часто privesc). Всегда id после доступа.
findmnt -no SOURCE / → устройство корневой ФС (для debugfs).
